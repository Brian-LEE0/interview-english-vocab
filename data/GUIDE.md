# 단어 데이터 작성 가이드 (모든 Day 공통)

기준 문서는 [../PLAN.md](../PLAN.md) 입니다. 이 가이드는 데이터를 쓸 때 지키는 규칙입니다.

## 파일

- Day 하나 = 100단어 = 세트 A~D 각 25단어
- 작성할 때는 세트별로 나눠서 저장: `data/parts/dayDD-A.json` … `dayDD-D.json` (각각 25개짜리 JSON 배열)
- `scripts/build_data.py` 가 4개를 합쳐 `data/dayDD.json` 을 만들고 검사합니다

## 한 단어의 형식

```json
{
  "id": "d01-A01",
  "day": 1,
  "level": 1,
  "set": "A",
  "family": "F1",
  "word": "expect",
  "pos": "verb",
  "ipa": "/ɪkˈspekt/",
  "meaning_ko": "기대하다, 예상하다",
  "category": "interview",
  "etymology": {
    "parts": [
      { "text": "ex",   "type": "prefix", "gloss": "밖으로" },
      { "text": "pect", "type": "root",   "gloss": "보다 (spect)" }
    ],
    "story": "밖을 내다보다 → 앞일을 내다보다 → 기대하다"
  },
  "example": {
    "q": "What do you expect from this role?",
    "a": "I expect to grow as an engineer and take on more responsibility.",
    "a_ko": "엔지니어로 성장하고 더 많은 책임을 맡기를 기대합니다."
  },
  "collocations": ["expect to do", "as expected", "meet expectations"],
  "related": ["respect", "inspect", "perspective", "prospect"],
  "tip": "지원 동기·기대치를 물을 때 바로 쓰는 단어"
}
```

## 필드 규칙

| 필드 | 규칙 |
|---|---|
| `id` | `dDD-SNN` (Day 두 자리, 세트, 세트 안 번호 01~25). 예: `d03-B07` |
| `level` | 1 기초 / 2 중급 / 3 고급 |
| `family` | 그 Day 의 어근 가족 (`F1`~`F10`). 핵심어(어근 없는 단어)도 그 Day 의 family 값을 씀 |
| `word` | 소문자 원형. 구동사·합성어는 `carry out`, `trade-off` 처럼 |
| `pos` | `noun` `verb` `adjective` `adverb` `phrasal verb` `phrase` 중 하나 |
| `ipa` | 미국식, 슬래시로 감쌈 |
| `meaning_ko` | 면접에서 쓰는 뜻을 먼저. 뜻이 여러 개면 쉼표로 2개까지 |
| `category` | `interview` / `it` / `negotiation` |
| `etymology.parts[].type` | `prefix` / `root` / `suffix` / `part`(합성어 조각) |
| `etymology.parts[].text` | 이어 붙이면 단어 철자가 되도록 (철자가 바뀐 어근은 gloss 에 원형 표기, 예: `"보다 (spect)"`) |
| `etymology.story` | 어원 뜻 → 지금 뜻으로 넘어가는 흐름을 `→` 로 한 줄 |
| `example.q` | 면접관 질문. 협상 단어는 리크루터·채용 담당자의 말 |
| `example.a` | **내가 면접에서 그대로 말할 수 있는 1인칭 답변**, 표제어를 그대로(또는 활용형) 포함 |
| `example.a_ko` | 자연스러운 한국어 번역 (존댓말 면접체) |
| `collocations` | 자주 쓰는 짝 표현 2~3개 |
| `related` | 같은 어근 단어 3~5개. **다른 난이도 단어 포함 가능** |
| `tip` | 언제 쓰는지 / 헷갈리는 단어와의 차이 / 발음 주의 등 한 줄 |

## 어원 정확성 (가장 중요)

- 사전에서 확인되는 어원만 씀 (라틴어·그리스어·고대 프랑스어 경로). **그럴듯하게 지어내지 않음**
- 민간 어원(틀린 속설)은 쓰지 않음
- 확실하지 않으면 잘게 쪼개지 말고 큰 단위로 나누고, story 를 단순하게
- 어근 가족에 넣은 단어는 그 가족의 어근을 실제로 가지고 있어야 함
- 가족 어근만으로 좋은 단어가 모자라면 **뜻이 같은 계열의 보조 어근**(예: F2 에 it·cur·ag)을 써도 됨 — 쓴 보조 어근은 PLAN.md §5 어근 표에 추가

## 난이도별 기준

`level` 은 **단어마다** 붙입니다. 하루 안에 세 난이도가 섞여 나옵니다.

| level | 단어 | 예문 `a` |
|---|---|---|
| 1 기초 | 중·고등 기본 어휘. 알지만 말할 때 바로 안 나오는 단어 | 짧은 1문장 (8~16단어) |
| 2 중급 | 업무·기술 일반 어휘 | 이유를 붙인 1~2문장 (12~25단어) |
| 3 고급 | 뉘앙스가 정확한 어휘, 시니어·협상 표현 | STAR 일부나 협상 멘트, 1~2문장 (15~30단어) |

PLAN.md §5 표에 있는 **다른 날의 대표 단어는 그날 몫이니 쓰지 않습니다.**
같은 어근 가족의 뒤 날짜(예: Day 1 → Day 11 → Day 21)는 앞 날짜 `data/dayDD.json` 에 이미 있는 단어를 쓰지 않습니다.

## 하루 100단어 구성 (숫자는 정확히 맞출 것)

- **어근 단어 90개 + 핵심어 10개** (핵심어 = 어근으로 쪼개기 어려운 합성어·구동사·게르만계 단어, 그날 주제에 맞춰). 핵심어도 level 을 붙임
- 난이도 비율 — 날이 갈수록 어려운 단어 비중을 늘림

  | 구간 | level 1 | level 2 | level 3 | 세트 A / B / C / D |
  |---|---|---|---|---|
  | 1구간 Day 1–10 | 50 | 40 | 10 | 13·10·2 / 13·10·2 / 12·10·3 / 12·10·3 |
  | 2구간 Day 11–20 | 30 | 50 | 20 | 8·12·5 / 8·12·5 / 7·13·5 / 7·13·5 |
  | 3구간 Day 21–30 | 20 | 40 | 40 | 5·10·10 (네 세트 모두) |

- 분야 비율 — 면접이 급해서 면접 단어를 앞쪽에, 협상·비즈니스는 뒤쪽에

  | 구간 | interview | it | negotiation | 세트 A / B / C / D |
  |---|---|---|---|---|
  | 1구간 Day 1–10 | 60 | 40 | 0 | 15·10·0 (네 세트 모두) |
  | 2구간 Day 11–20 | 50 | 40 | 10 | 13·10·2 / 13·10·2 / 12·10·3 / 12·10·3 |
  | 3구간 Day 21–30 | 20 | 25 | 55 | 5·6·14 / 5·6·14 / 5·7·13 / 5·6·14 |

  - 1구간에서 value, salary, benefit 같은 돈 관련 단어는 **면접에서 묻는 맥락**(희망 연봉, 지원 동기 등)으로 써서 `interview` 로 분류
- 세트 안에서는 같은 어근끼리 붙여서 배치 (어근 → 그 어근 단어들, 쉬운 단어 → 어려운 단어 순). 핵심어는 각 세트에 2~3개씩
- PLAN.md 의 그날 대표 단어는 반드시 포함하고, 표에 적힌 난이도를 그대로 씀
- 한 Day 안에서 같은 단어 중복 금지. 같은 원형의 파생어(expect / expectation)는 하루에 2개까지
